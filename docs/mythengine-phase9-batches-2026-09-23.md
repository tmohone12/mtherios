Status: Phase 9 gate complete in the isolated MythEngine checkout; billed-cost savings are unproven.

The isolated PostgreSQL database was backed up to `data/backups/phase9-pre-batch-2026-09-23.dump` before migration 0044 was applied. Migration 0044 adds batch, child and target ledgers and permits project-owned `assistant_batch_child` outbox jobs. The Assistant `subagent` tool separates a revision-bound plan from dispatch. Planning enumerates every active document of one exact type and project/game scope (up to 500), stores a representative sample and all expected item revisions, and assigns at most ten targets per child. Dispatch is idempotent and queues the existing outbox jobs. The batch setting and `batchAuthoring` service profile are checked separately from the Assistant profile.

Each child receives only its assigned record snapshots, objective, instructions and allowed field schema. It receives no parent conversation or tools. Its bounded provider request has no provider retries. A durable marker is written before the request: if the response is lost, automatic retry fails for review instead of making another paid call; if a proposal was saved, retry resumes unfinished item applications without calling the provider again. The server validates one decision for every assigned ID, permits updates only to planned data fields, and commits through the canonical content writer with batch/run/call attribution. A fresh item/type/scope revision check happens inside each item transaction. Cancellation marks unstarted targets and queued jobs; a late child cannot commit after cancellation. Exhausted jobs are reconciled into durable child/target failures when the conversation is read. The panel reads these rows from PostgreSQL, shows child/item outcomes and separate Subagents usage under the initiating message, and can stop a batch.
