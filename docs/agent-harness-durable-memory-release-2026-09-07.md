# Agent harness durable scene projection — 2026-09-07

## Slice 4 increment

The existing `refresh_scene_checkpoint` job now extends the stored primary-POV checkpoint with a bounded structured projection. It is still written into the story metadata atomically under the existing story lock; no parallel memory service or obligation ledger was added.

The projection contains:

- source-linked participants from visible committed canonical events;
- completed canonical beats;
- explicit unresolved thread and agreement actions;
- current active or contested agreement pointers and parties;
- pointers to source-linked visible facts and actor beliefs.

The projection is deterministic. It filters non-canon, secret, superseded, and closed records, intersects emitted source IDs with the checkpoint window, preserves canonical agreement/thread IDs, and leaves unknown status unknown. Prompt assembly exposes only bounded source-linked IDs and summaries, while the existing canon and belief sections remain authoritative.

Chapter and arc memory nodes now also carry deterministic projection fingerprints, compiler identifiers, campaign/source-range/branch metadata, and primary-POV scope. Arc memory nodes retain their source-entry IDs instead of dropping them during rollup, so older arc context remains independently traceable to original evidence.

The existing saga table now has a scheduled rollup path. A new arc enqueues one deduplicated `rollup_saga` job; the worker groups five uncovered arcs, writes a stable source-linked saga projection, and preserves active thread IDs only. Fewer than five uncovered arcs remain pending rather than producing a partial saga.

Prepared turns now fingerprint provider/generation inputs and revalidate the story server revision plus the persisted narrative-service settings before a cached preparation can be consumed. Canonical sync edits, transcript deletion, turns, and replacement imports therefore force a rebuild through the existing story revision path; a model or prompt-setting change also invalidates the preparation. World-database replacement imports advance the revision even when the exported revision is unchanged.

The app-status contract now reports a stable `package@version` build identity with source, artifact, and optional external build ID. The long-running process was intentionally not restarted during the earlier source change; the later isolated verification instance below proves the identity on the current build without claiming production activation.

The prepared request path now computes one dynamic-context allowance after reserving fixed serialized input, configured output, and provider framing. Automatic and manually oversized budgets are clamped before provider dispatch; if protected request material alone cannot fit, preparation returns an actionable capacity error instead of silently changing the action or dropping the rules.

Structured NPC belief writes now apply the same source-position guard already used for agreements: repeated sources are ignored, and an older extraction cannot overwrite a newer same-topic belief. Historical evidence remains available through the original belief rows and source references.

Model capacity is now an explicit part of the existing LLM service settings. contextWindowTokens is optional, visible in World Explorer, configurable through the existing settings command, and carried into provider capability checks. When present it overrides the model registry for both preparation and the final serialized-request guard; preview receipts report explicit-override instead of presenting the registry/default estimate as authoritative. Migration 0018_llm_context_window_override.sql is additive and must be applied with the normal migration step before activating this source build.

The existing generation qualification harness now supports repeated deterministic rounds and reports duration p50/p95 plus cache assembly timings. Five 10,000-turn rounds completed at 1/3 ms p50/p95 on this checkout, retaining 80-entry projections, 120-entry prompt windows, four of four warm stable-segment hits, and one invalidated character segment. The disposable DB-backed 1,000-turn fixture seeded 2,000 entries in 251 ms, served bounded projection/transcript/bootstrap reads in 54 ms, and cleaned up its generated story. These are local control-surface measurements, not provider latency or narrator-quality claims.

Benchmark and replay reports now include a working-tree build identity, Git HEAD, dirty-status fingerprint, and selected source hashes. This closes the Slice 0 evidence ambiguity where HEAD alone could describe the wrong checkout.

Chapter, arc, saga, and their durable memory-node upserts now use monotonic serverVersion conflict guards. A late worker can still finish its read/LLM work, but an older projection cannot replace a newer persisted projection on conflict; the existing deterministic fingerprints remain available for diagnosis and rebuild.

Projection workers now revalidate their source snapshot immediately before persistence. Chapter jobs compare source entry and event identity, position/content, status, and source versions; arc and saga jobs compare their upstream projection versions, fingerprints, and source-ID ranges. A changed dependency returns a retryable stale-projection result instead of committing derived state from an obsolete read. Each chapter/arc/saga row and its durable memory node are now written in the same database transaction, so a failed companion write cannot leave the projection half-applied.

Provider usage now preserves a reported USD cost when the provider returns one, plus provider cached-input and cache-write counters, through generation timings, aggregate turn performance, and API-call metadata. The UI labels application cache reuse separately from provider cache tokens, labels reported cost `provider cost`, and displays `unavailable` rather than inventing a local estimate. Memory coverage recovery is also exposed for outdated sources, not only missing sources, so stale evidence can use the existing bounded recovery path.

Job status now classifies active failures by story, stage, cause, source version, and retryability. The classifier recognizes provider-account, malformed-output, capacity, stale-source, validation, unavailable, and unknown failures; the existing status payload keeps raw bounded errors while exposing grouped `failureClasses` for actionable recovery decisions. Existing planner output-limit failures were verified live as `capacity` and non-retryable, so the runtime does not invite blind retries.

Memory processing status now separates turn-extraction coverage from three durable-stage signals: scene checkpoint, chapter/arc/saga consolidation, and optional vector/canonical/wiki indexing. Each stage reports current, updating, needs attention, or not run yet from the existing job rows, with bounded counts and the latest source version available for inspection. The reader status card keeps the source-coverage recovery action separate from projection/index health so a healthy extraction stream cannot hide a stale downstream projection.
