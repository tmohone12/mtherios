# Phase 3 writer coverage audit

Date: 2026-09-22. This is a source inventory of the isolated MythEngine working copy, paired with the disposable live checks in `phase3-live-proof.json`. It covers the authoring surfaces enabled at this cutover; future GM/Assistant mutation tools are still gated.

| State / write route | Revision capture | Projection / outbox boundary |
| --- | --- | --- |
| Custom type create/edit, import, reviewed layout clear, history restore (`content.ts`) | `content_revisions` type snapshot in the project-locked transaction; revision starts at 1 and increments on edit/restore | No type projection consumer exists yet. Phase 4 prompt policy will read current definitions and establish invalidation. |
| Custom document create/replace/update/move/copy/archive/recover, folder subtree moves/copies/archive/recover, remapped import (`content.ts`) | `history(tx,'item',...)` for every inserted or revised document, including archived rows and restored versions. Folder changes also receive folder history. | Custom documents are canonical PostgreSQL rows; there is no custom-document vault/index job to enqueue yet. Phase 4 owns prompt consumption. |
| Game migration (`gameMigration.ts`) | Game-owned documents and folders increment revision and write history. Imported shared dependencies receive creation baselines. Canonical envelopes increment and append history. | Migration queues the existing story vault sync job in the same transaction as ownership and history. |
| Canonical source rows: characters, locations, items, factions (`drizzle/0024_canonical_content_history.sql`) | Database triggers capture insert, update and delete from `entities`/`factions`, regardless of browser, backend turn, extraction, import, repair script or direct SQL writer. Existing rows received one truthful migration baseline, not invented older versions. | `patchWorldRecord` writes state patch/audit and queues vault and canonical-index jobs in its transaction. Other backend writers retain their established job cadence; the trigger guarantees the source snapshot, not a new projection job for each automatic update. |
| Canonical workspace envelope create/edit/folder/archive/import/restore (`canonicalContent.ts`) | `saveMetadata` appends `canonical_content_history` atomically. A source edit triggers a source-row history version. | Domain edits and restores call `patchWorldRecord` in the same transaction, retaining its outbox. Envelope-only metadata has no Phase 3 projection consumer. |
| Built-in type save/import/reviewed clear/restore and missing-default migration (`canonicalTypes.ts`) | Revision 0 baseline is inserted before first edit; every later type version is inserted into `canonical_type_history`. Default migration patches each record through `patchWorldRecord` in the type transaction. | Migrated domain records receive the canonical writer's outbox. Type-only changes are consumed from current project settings; Phase 4 adds prompt invalidation. |

Repository SQL search for direct `content_items`, `content_types`, `canonical_content` and `canonical_type_settings` writes found the owning modules above. `drizzle/0024_canonical_content_history.sql` was inspected separately for source-row trigger coverage; script writers are covered by the database trigger, not a generic patch assumption. The history, document/type update and outbox writes share their caller transaction where an outbox is applicable. A disposable trigger forced a `content_revisions` insert failure and proved both the document mutation and revision count rolled back.

Retained history reconstructs versions from the catalog cutover forward. Remapped imports establish truthful destination baselines; they do not transport every source revision. Custom-document prompt indexing and invalidation belong to Phase 4, and agent write routes remain unavailable until their later phases.
