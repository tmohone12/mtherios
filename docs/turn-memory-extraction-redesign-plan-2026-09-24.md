# Turn memory extraction redesign — implementation plan

**Status:** plan, 2026-09-24. No pipeline change is claimed here. This refines the Turn Memory delivery path in [the GameMaster and Memory & Context consolidation plan](mythengine-memory-context-consolidation-plan-2026-09-23.md); it does not change who owns canon, chapter cadence, or Jev actor decisions.

## Requested result and observed baseline

Completing a GameMaster turn should leave a durable, source-linked memory decision without routinely making a second generative model reread the prose. The player should see whether memory is current, awaiting bounded consolidation, or delayed by a provider cooldown. Live turns should not wait behind historical extraction or projection work.

Current source explains the backlog:

- [`shouldExtractDurableState`](../src/lib/server/turn/orchestrator.ts) treats almost every non-OOC turn as extractable; deferred mode publishes one `extract_turn_state` job per source pair.
- [`processor.ts`](../src/lib/server/jobs/processor.ts) calls the classifier per job and may call it again to repair invalid output. Jobs for one story run sequentially, even when the worker claims a larger batch.
- [`provider.ts`](../src/lib/server/turn/provider.ts) immediately retries transient HTTP failures inside a generation request. [`outbox.ts`](../src/lib/server/jobs/outbox.ts) then has its own job retry schedule and gives extraction priority over scene checkpoints.
- The turn validator in [`patchValidator.ts`](../src/lib/server/turn/patchValidator.ts) verifies persisted player and narration sources and enforces primary versus parallel-POV scope. A multi-turn text blob cannot safely be passed to it as though it were one turn.
- [`memoryCoverage.ts`](../src/lib/server/jobs/memoryCoverage.ts) measures coverage per eligible source pair and stops the contiguous boundary at a gap. That accounting must survive the redesign.

At the 2026-09-24 planning snapshot, `npm run app:status` showed the MythEngine worker enabled for `all` scopes, a large extraction backlog, and Veil failures from empty or malformed classifier responses. Those counts are volatile; capture a fresh baseline before implementation. The older consolidation plan's statement that the worker is disabled is no longer current.

## Target contract

1. **One completed turn, one durable memory receipt.** Persist narration, a versioned `MemoryCandidateEnvelope`, and a processing receipt tied to `storyId`, player entry ID, narration entry ID, source hash, branch/POV scope, and story version. The envelope contains zero or more proposed changes; zero is an explicit, auditable no-change proposal, not a skipped source. Each candidate names a supported operation/record type and target ID where applicable, quotes or offsets into the persisted source, and labels `observed_event`, `proposal`, `belief`, or `uncertain`. Include visibility and belief owner. A candidate is never canon by itself.
2. **Preserve streaming prose.** Extend the server provider/agent turn contract so visible text streams normally while hidden structured changes arrive as a separate validated tool result or final envelope. Do not expose metadata in the story prose or assume streamed `text` can contain native tool calls: today's [`provider.ts`](../src/lib/server/turn/provider.ts) streaming path returns no tool calls. Reject malformed metadata into bounded fallback without discarding a completed narration. Persist the final parsed envelope and its validation errors with the turn receipt.
3. **Use deterministic evidence first.** Successful inventory, damage, movement, agreement, faction, and other engine operations with structured receipts create candidates directly. Deduplicate these against GM proposals by source/operation/target. Apply only through the existing canonical validator/writers and their version, authorization, source, and idempotency guards. A proposed event or a character's claim cannot become an accepted event merely because the GM described it.
4. **Ask Jev only bounded questions.** For ambiguous candidates, build one typed Decisions API request with independent questions such as occurrence versus proposal, lasting versus scene-only versus belief, actor knowledge, and whether a specific existing fact is superseded. Supply exact candidate and evidence IDs; do not ask Jev to write summaries, free-form facts, or canonical JSON. Validate returned IDs, confidence, evidence support, and scope in code. Calibrate memory-specific thresholds on reviewed examples rather than reusing the NPC-reaction threshold. If Jev is unavailable, low-confidence, or rate-limited, leave the candidate pending for Memory & Context; never silently accept it.
5. **Keep a bounded exception path.** Missing or ambiguous facts enter one recoverable per-story pending source range, partitioned by branch/POV and historical versus live timeline. Flush after an initial three-to-five-turn *maximum* window, a token budget, a scene/chapter boundary, or before the next turn that needs a critical fact. These numbers are starting limits to tune from measurements, not a promise that every window fits. The generative Memory & Context pass may read a window once, but must emit separate source-pair updates. Apply each through the existing validator with its own persisted IDs and versions, in chronological order. A failed source remains pending and visible; successful later sources do not close its coverage gap.
6. **Keep recent dialogue available while pending.** The prompt's bounded recent-dialogue path remains the immediate source for ordinary conversation. Do not label pending dialogue as accepted memory, and do not let unresolved critical state (inventory, injury, agreement, location, disclosed secret) disappear from the next relevant prompt. At chapter creation, preserve the existing complete chronological source-account checks; chapter summaries do not replace per-turn memory receipts.

## Invariants and qualification

- PostgreSQL transcript and canonical records remain authority. GM metadata, Jev answers, and fallback output are proposals until accepted by the existing writers. Retain accepted canon, belief, scene detail, future intent, and OOC instructions as separate types.
- Every candidate and decision carries the exact source pair and visibility/branch/POV scope. Batch *requests* may contain multiple candidates; batch *application* must still respect individual source/version guards. Never give one POV another's private evidence through Jev, Memory & Context, or the next GameMaster prompt.
- Live play has scheduling priority. Historical repair is evidence-only when newer narration exists and never replays world ticks, NPC actions, or turns. Retain pending-versus-activated faction/Director state.
- Measure both total provider requests and correctness before the next relevant turn. Do not declare success based on worker throughput alone. Release gate: reviewed Veil sample has no unsupported accepted facts, no POV/visibility leaks, no lost source coverage, and no stale-state overwrite; request count and p95 lag improve from the recorded baseline. Set numeric performance targets after Phase 0 rather than inventing them here.
- Tests: focused `provider.test.ts`, `orchestrator.test.ts`, `patchValidator.test.ts`, `jev.test.ts`, `outbox.test.ts`, `processor.test.ts`, and `memoryCoverage.test.ts`; add integration cases for stream-plus-envelope, 429 cooldown, crash resume, batched per-source apply, historical backfill, and parallel POV. Run `npm run check` and build after implementation. Then inspect a built live prompt packet, saved receipts, status UI, and a controlled non-mutating provider check before any limited real-turn rollout. Benchmark/job-drain modes may mutate data or spend provider calls, so scope them to fixtures or explicit rollout windows.

## Rollback boundary

Keep the old extractor readable until new receipts cover every eligible source in a migrated story. A feature flag reverts *new* turns to the existing durable `extract_turn_state` route; it does not delete accepted canon or replay completed turns. Reconciliation uses source fingerprints and receipt versions to enqueue only genuinely missing work. Remove the old routine path only after the reviewed sample and live gates pass.
