The engine command path creates, lists and reads conversations; sends a message through the separately configured `assistant` service; and cancels a running reply. A message ID makes send retries idempotent. The server binds a run to its original conversation scope, gives the provider a bounded directory of shared/game documents plus up to 12 recent game messages, stores model/token/cost usage, and saves source IDs mentioned in the reply. A provider error or interrupted lease leaves a failed run visible; cancellation prevents a late generated reply from committing.

Conversation compaction now uses the existing `assistant_conversations.summary` and `summary_sources` fields. Before each reply, the server transactionally folds committed messages older than the latest 12 into short excerpts, source IDs/revisions and completed edit/question/approval receipts. It keeps the last 24 excerpts and 48 receipts in a 12,000-character digest, caps stored source references at 500, and leaves full messages/tool results in PostgreSQL. The digest is sent beside the current request; prior receipts are explicitly excluded from proving a current-run edit. The cursor uses PostgreSQL's exact timestamp text to avoid refolding rows when microseconds are present.
