# Turn jobs replace the background job worker — 2026-10-11

Status: implemented on branch `memory/turn-owned-jobs`, based on `69d4d22`. This is a dated working record; [ARCHITECTURE.md](../ARCHITECTURE.md) owns the current description.

## Why

The polling worker (`jobWorker`, one job per 5-second tick, off by default) left memory behind the story. With it off, the live campaign's memory stopped: no job completed after 2026-10-08 00:27, and Veil reached turn 2,418 with 262 narrated turns never extracted, about 8 chapters unsummarized and 5,922 jobs queued.

## What changed

- **No poller.** [turnJobs.ts](../src/lib/server/jobs/turnJobs.ts) runs a story's queued jobs in the app process as soon as the work that queued them is saved: immediately after a turn, one second after any other enqueue (so its transaction can commit). `mtheriosd` no longer starts a worker; `jobWorker`, `jobWorkerScope`, `jobIntervalMs`, `jobTimeoutMs` and `jobBatchLimit` are gone (a leftover `jobWorker` key in a config file is ignored).
- **Memory is never behind.** Per story, memory jobs run first in claim-priority order: extraction, scene checkpoint, memory nodes, embeddings, canonical index, vault sync, chapters and their consumers, arc/saga rollups, summary rebuilds. A turn waits for its story's due memory jobs before it reads context: an agent run waits after claiming its lease (heartbeat running) and before its time budget starts; a direct `processServerTurn` waits in `prepareServerTurnContext`. A cancelled turn stops waiting; the jobs continue.
- **World jobs don't block.** Faction pressure, world simulation and Director forecasts run after memory at their existing cadences and never hold a turn up. Project jobs (cover images, settings checks, assistant batches) have their own lane.
- **Retries.** A backoff under 15 minutes wakes its lane once when due; a longer one waits for the story's next turn. Failures stay on their rows and never fail a turn.
- **Clean async context.** Jobs start outside the queuing request's async stores ([requestScopes.ts](../src/lib/server/requestScopes.ts)): provider hooks and budget, query-embedding reuse, ChatGPT owner, assistant connection. Without this, an extraction started from inside an agent run tried to checkpoint that run and failed with "Run stopped before its checkpoint" (seen once in the runtime check, then fixed).
- **Off switch.** `turnJobs: false` / `MTHERIOS_TURN_JOBS=false` for tests (set in `vitest.config.ts`), evals, fixtures and isolated copies (now required there). `jobs.runDue` / `POST /api/app/jobs/run` still run jobs by hand, with a new `scope: "memory"` beside `"faction"`.
- **Continuity Review retired.** No turn read its warnings (`continuityWarnings: []` in turn context). The `continuity_audit` job is no longer queued; older rows complete without work; the `continuityReview` task is marked retired. Its deterministic due-faction-project check moved into `update_faction_pressure`.
