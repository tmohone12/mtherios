# Turn jobs replace the background job worker — 2026-10-11

Status: implemented on branch `memory/turn-owned-jobs`, based on `69d4d22`. This is a dated working record; [ARCHITECTURE.md](../ARCHITECTURE.md) owns the current description.

## Why

The polling worker (`jobWorker`, one job per 5-second tick, off by default) left memory behind the story. With it off, the live campaign's memory stopped: no job completed after 2026-10-08 00:27, and Veil reached turn 2,418 with 262 narrated turns never extracted, about 8 chapters unsummarized and 5,922 jobs queued.

## What changed

- **No poller.** [turnJobs.ts](../src/lib/server/jobs/turnJobs.ts) runs a story's queued jobs in the app process as soon as the work that queued them is saved: immediately after a turn, one second after any other enqueue (so its transaction can commit). `mtheriosd` no longer starts a worker; `jobWorker`, `jobWorkerScope`, `jobIntervalMs`, `jobTimeoutMs` and `jobBatchLimit` are gone (a leftover `jobWorker` key in a config file is ignored).
- **Memory is never behind.** Per story, memory jobs run first in claim-priority order: extraction, scene checkpoint, memory nodes, embeddings, canonical index, vault sync, chapters and their consumers, arc/saga rollups, summary rebuilds. A turn waits for its story's due memory jobs before it reads context: an agent run waits after claiming its lease (heartbeat running) and before its time budget starts; a direct `processServerTurn` waits in `prepareServerTurnContext`. A cancelled turn stops waiting; the jobs continue.
- **World jobs don't block.** Faction pressure, world simulation and Director forecasts run after memory at their existing cadences and never hold a turn up. Project jobs (cover images, settings checks, assistant batches) have their own lane.
- **Retries.** A backoff under 15 minutes wakes its lane once when due; a longer one waits for the story's next turn. Failures stay on their rows and never fail a turn.
- **Clean async context.** Jobs start outside the queuing request's async stores ([requestScopes.ts](../src/lib/server/requestScopes.ts)): provider hooks and budget, query-embedding reuse, ChatGPT owner, assistant connection. Without this, an extraction started from inside an agent run tried to checkpoint that run and failed with "Run stopped before its checkpoint" (seen once in the runtime check, then fixed).
- **Off switch.** `turnJobs: false` / `MTHERIOS_TURN_JOBS=false` for tests (set in `vitest.config.ts`), evals, fixtures and isolated copies (now required there). `jobs.runDue` / `POST /api/app/jobs/run` still run jobs by hand, with a new `scope: "memory"` beside `"faction"`.
- **Continuity Review retired.** No turn read its warnings (`continuityWarnings: []` in turn context). The `continuity_audit` job is no longer queued; older rows complete without work; the `continuityReview` task is marked retired. Its deterministic due-faction-project check moved into `update_faction_pressure`.

## Live deployment and catch-up (2026-10-11)

Deployed as `88468c2` after a backup (`data/backups/mythengine-before-turn-jobs-20261011.dump`), started with turn jobs paused for a one-time catch-up. 2,766 queued non-memory jobs and 312 extraction jobs older than the Oct 8 gap (or whose narration no longer exists) were marked `cancelled` with the reason in `metadata.cancelled`; nothing was deleted.

The catch-up exposed two extraction faults on the live Classifier (`google/gemini-3.8-flash` via OpenRouter), fixed and deployed on the way:

- `280c1ec`: Gemini rejected every strict state-patch schema ("Request contains an invalid argument"; all 50 schema calls failed, 934 non-schema calls succeeded), so extraction had never worked on this model. Gemini now gets JSON mode. The scene header also stopped forcing reasoning off, which this model rejects ("Reasoning is mandatory").
- `d81d61c`: in JSON mode about 4 in 10 answers stayed invalid after their repair, discarding the whole turn. The parser now drops only malformed list items and unknown keys and validates the rest; afterwards 5 of about 190 failed.

Outcome when the OpenRouter key hit its weekly limit ("can only afford 1482 tokens", 402) and the catch-up was stopped: 167 of the 268 recent-gap turns extracted, about 92 still queued, 16 failed on the credit limit (re-queue after a top-up), 10 interrupted by a Docker Desktop stop and returned to the queue, 5 failed on model output. No missing chapter was written yet. Spend since the catch-up began: $6.67 (188 successful calls $3.28; 220 failed or repaired calls $3.39). Extraction is about $0.04 per turn here because Veil's context exceeds the 12,000-token batch limit, so turns are not batched.

After credits were restored the catch-up finished: every memory job ran (2,239 of 2,247 on Veil; the 8 failures are arc rollups, below), chapters 92-99 were written in the concise format, and 14 turns now sit after the last chapter. 865 redundant search-index runs and 28 stale world-simulation and Director jobs were cancelled. Total spend from the start of the catch-up: $11.12 over 668 calls.

- `fe67b70`: without embeddings the search index rewrote an identical "skipped" marker for every canonical record (about 51 s per run on Veil) and sat in the memory lane, so a turn would have waited for it. Unchanged markers are now skipped and the index runs after memory with the world jobs. Live since this restart, with turn jobs on.
- Arc 10 cannot be written yet: arc 9 covers only chapters 81-86, so chapters 87-96 form the next window, but chapters 88-90 (external reviewed drafts spanning 63 turns each) store 210-224 KB of turn accounts apiece, over the 50 KB arc input limit. The rollup refuses before any request.
- The Journey's next chapter window is also over budget ("Combined chapter summary exceeds the prompt budget; validated subwindows were retained"); its subwindow summaries are kept.
- Ten extraction jobs interrupted by the Docker stop ran as compact recovery attempts, which get no repair or salvage, and seven failed; they were re-run as first attempts. A retried extraction still skips repair and salvage.

Both size limits were then fixed in `b2c7c57` and `5b049b3` (summary compiler v5, so the stored size failure no longer replays): Veil's arc 10 (chapters 87-96) and The Journey's chapter 10 were written in the concise format for about $0.59.
