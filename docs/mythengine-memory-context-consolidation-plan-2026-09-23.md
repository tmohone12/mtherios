# MythEngine GameMaster and Memory & Context consolidation plan

**Status:** partially implemented, 2026-09-23. The provider grouping, saved-setting migration, retired Style Review/Action Choices/Wiki Lint paths, Turn Memory task identity, and bounded Jev faction/NPC jobs are built and running. The server job worker is currently disabled, so background moves are not live-exercised. The proposal-first backend lore job, reviewed Refine entry action, and representative campaign replay remain open qualification work.

## Requested result

Make **GameMaster** the primary story model and the visible name for today's Narrative model. World State and related services become GameMaster tools, rather than a competing top-level provider group. Give GameMaster two bounded subagents: **Memory & Context**, including actual completed-turn memory, lore upkeep, and entry refinement; and **Player Guidance**, for optional player-facing suggestions. Retire standalone Style Review and Wiki Lint. Keep lore search and context working. Use the consolidated evidence path to support Jev choices for background faction moves and independent NPC actions.

Interpretation of the requested cleanup: remove the standalone Style Review service and its after-turn call; fold the Lorebook model group, Lore Management, and Entry Refinement into Memory & Context; retire both the unused AI Wiki Lint service and the separate user-facing `wiki.lint` workflow. Structural validation of canonical writes and wiki search/context remain required.

## Target boundary

GameMaster owns narration, the turn boundary, and the decision to request bounded help. Keep the persisted `narrative` service ID as a compatibility alias at first; change its user-facing name to **GameMaster** in provider settings, prompt settings, receipts shown to users, and relevant help text. The GameMaster model selected in the primary control must be the model that actually receives the prepared turn. World State tasks (`classifier`, `smallBrain`, `activeRecall`, `actorDecision`, `continuityReview`, `characterUpdate`, `worldSimulation`, and strategic simulation) are typed tools or jobs invoked around that turn, with their own validated output contracts. They do not own another independent campaign state or appear as another primary provider. Jev can be selected as a tool-specific decision override; it must not become the prose or extraction model.

The provider screen should present GameMaster, Memory & Context, Player Guidance, and Image Generation as clear functional areas, with Authoring Assistant separately for authoring. GameMaster's World State and deep-simulation controls live under an expandable **Tools** area. Memory & Context and Player Guidance show their subagent model, enablement, budget, and effective fallback to GameMaster where appropriate. Batch Authoring belongs under Authoring Assistant. A functional area or subagent does not imply its own provider account: use the GameMaster provider by default and expose a model/provider override only when needed. Preserve every explicit existing override, provider/key reference, and enabled flag during migration; never silently run an old specialist on the GameMaster model. The effective model for each task must remain inspectable in the UI and request receipt.

The two GM subagent paths use one server orchestration contract: a named task, bounded and visibility-filtered input, allowed read/submit-proposal tools, output schema, time/token/cost ceiling, source receipts, and a deterministic fallback. They cannot call `turn.submit` or write canon directly. Existing Assistant batch subagents do not supply this GM path. Turn Memory runs when state extraction is enabled; Player Guidance runs only when requested. Reuse existing jobs and scheduling so the consolidation does not add an unconditional extra model call to every turn.

The Memory & Context subagent is the owner of **preparing and checking evidence**, including completed-turn memory. It coordinates existing backend jobs and tools rather than storing a second version of the story:

1. Read PostgreSQL transcript evidence, accepted canon, NPC beliefs, faction goals/projects, and retained source IDs at the correct story version.
2. Process each completed turn through the existing `extract_turn_state`/checkpoint path, then maintain chapter, arc, and saga projections at their existing cadence; retrieve bounded lore and memory for GameMaster; flag semantic duplication, conflict, or incomplete support for review. A failed extraction remains pending or failed and retryable, never represented as accepted memory.
3. Propose lore entry creation, refinement, merge, or archive with exact target IDs, before/after fields, evidence, visibility, and record revision. Automatic merge/archive requires review. Commit accepted changes only through canonical write contracts, then refresh vault/index projections.
4. Provide distinct **faction-scoped** and **NPC-scoped** evidence packets for world decisions. A faction packet may include its own goals, resources, eligible projects, known events, and permitted targets. An NPC packet uses the existing actor decision view so hidden narrator knowledge does not leak into the actor's decision.

The Player Guidance subagent receives the current player-visible scene, player capability, and permitted choices; it returns optional suggestions with short reasons. It must not consume GM-only secrets, set player intent, submit a turn, or advance the world. Fold Action Choices into the same path only if a live caller needs them; otherwise remove the orphan after compatibility checks.

GameMaster still writes story prose. Jev receives only bounded choice, yes/no, or score questions; it does not generate chapter accounts, lore descriptions, or action text. Model outputs are proposals until the relevant validator and writer accept them.

## Delivery sequence

### 1. Record the baseline and migrate settings

- Inventory saved browser `serviceConfigs`/`profileModels` and server `llmServiceSettings`, prompt overrides, enabled flags, and provider/key references. Record which settings are actually used by backend-bound versus local-only stories.
- Add a versioned, idempotent settings migration. Keep the persisted `narrative` ID as the GameMaster compatibility key. Migrate `worldState` and `deepSimulation` profile settings to GameMaster tool defaults or explicit tool overrides; `guidance` to Player Guidance; `lorebook` to Memory & Context. Prefer an explicitly saved Memory & Context model; otherwise adopt the saved Lorebook model. Preserve any explicitly different specialist model as a visible task override until the user changes it. Never copy a raw API key into the browser or database.
- Make GameMaster the primary provider/model control and show World State services under its **Tools** controls. Define Memory & Context and Player Guidance as GM subagent areas, with task enablement and budgets. Keep chapter/arc/saga jobs and guidance output schemas distinct internally even if they inherit the same provider. Update `SERVICE_PROFILES`, `ServiceConfigPanel.svelte`, `SettingsModal.svelte`, `PromptsPanel.svelte`, browser/server sync, descriptions, and documentation together. Keep `narrativeSettings` and terminal `narrative` as compatibility fields until an explicit later migration proves all consumers moved.
- Gate: after reload and server refresh, an existing configured story retains the effective model, enabled state, prompt overrides, and key reference for each task. Fresh installs show GameMaster as primary, World State as Tools, and no competing Narrative, World State, Player Guidance, Lorebook, or Style Review provider cards. A test turn receipt identifies the selected GameMaster model and any tool overrides.

### 2. Establish GM subagent and tool ownership

- Add the GM-scoped bounded subagent contract and receipts. Route optional Player Guidance requests from the visible scene through it; return suggestions for the player to choose or ignore. Confirm whether Action Choices has a production consumer, then fold it into Guidance or remove it with a compatibility path.
- Wire the Memory & Context Turn Memory task to completed-turn state extraction and downstream summary scheduling. Let existing server jobs and canonical writers commit accepted results; enforce turn/story version checks, source IDs, retry idempotency, and separate statuses for generated proposal versus applied memory. Do not shift turn extraction into browser storage or a second database.
- Reclassify classifier, recall, actor decision, continuity review, character update, world simulation, and strategic world brain as GameMaster tools/jobs. Preserve their distinct prompts, output schemas, provider capabilities, and enablement. Add an effective-settings view and server tests proving a tool with an override uses it while an inherited tool uses the GameMaster provider.
- Gate: GameMaster alone submits prose turns; both subagents stay within their tool grants and budgets; a failed Turn Memory job retries without duplicating state; suggestions never become player actions; old saved provider choices still route to their intended tasks.

### 3. Consolidate lore and remove duplicate services

- Add `memory_context` to the orchestrator role contract and route new `memory` and `lore_curation` plans through it. Map legacy role IDs when reading old run receipts. Remove the `wiki.lint` call from lore curation.
- Keep `summaryGeneration.ts` and the durable outbox as the backend-bound history path. Replace the browser-triggered lore pass for backend-bound stories with one versioned, deduplicated server job after chapter persistence. A retry checks the source snapshot and does not repeat already accepted changes.
- Make lore maintenance proposal-first. Retain historical transcript, accepted current fact, NPC belief, future intent, and public/secret visibility as separate inputs. Require source coverage and record revisions before application; keep local-only stories on an explicit compatibility path until migrated.
- Put the manual Refine entry flow under Memory & Context in World Explorer or the existing entry editor. Preview changed top-level fields against the loaded baseline, validate record type, then apply only those fields through the shared patch command. Do not overwrite other edits made since the preview.
- Gate: 20 complete turns still produce one chapter, 10 consecutive chapters still produce one arc, every source account remains represented, backend-bound lore runs once, and reviewed edits agree in PostgreSQL and the vault projection.
- Delete the optional after-turn Style Reviewer dispatch and warning UI, its old client service/registry entry, profile, and prompt selector. Keep relevant narrative instructions and the distinct source-linked Continuity Review service.
- Delete the unused AI Wiki Lint service and schema when all references are removed. Retire `wiki.lint` from engine commands, `/api/wiki/lint`, app/wiki CLI flags, wiki auto-lint config, Canon Repair/World Drawer controls, and lore curation plans. Preserve wiki search/context and import/write validation. Update tests and help text so no dead settings or lint buttons remain.
- Gate: a normal turn makes no Style Reviewer or Wiki Lint model call; wiki/context retrieval and source-linked lore pages still work; retired routes/commands have an explicit compatibility result if old clients can call them.

### 4. Feed Jev from the consolidated evidence path

- Reuse [`jev.ts`](../src/lib/server/turn/jev.ts) as the server-only decision transport. Extend it with typed, validated requests and saved model/usage/source receipts, rather than creating separate clients per feature.
- At the existing faction world tick, enumerate eligible moves and a **hold** option in code. Jev chooses among those concrete options using the faction-scoped packet. The current faction planner still computes progress, validates participants/resources/targets, and writes the secret move plus its delayed public signal. Timeout, missing evidence, or low confidence uses the existing deterministic choice or hold.
- Add a bounded NPC background job at an explicit campaign turn/chapter boundary. Select actors with a real opportunity and no duplicate action in that window. Build each actor's isolated view and concrete eligible actions, including **wait**. Jev selects one; the job validates the actor, target, time, and visibility before saving a source-linked event and updating `lastIndependentAction`. Future plans remain intentions until an event is committed.
- Gate: neither decision path invents a player action, reveals an NPC's unknown secret, advances a blocked project, repeats an action on retry, or turns a pending intent into an accomplished event. The next narrator packet can show the new event only at the appropriate visibility and time.

## Qualification and release gates

- Add focused tests for settings migration and effective model routing, GM subagent permissions and receipts, optional player guidance, Turn Memory retry/idempotency, orphaned service removal, the Memory & Context role/tool plan, complete summary coverage, lore proposal/revision behavior, Jev response validation, and faction/NPC retry and visibility boundaries.
- Replay representative campaigns with known corrections, parallel POV, secret NPC knowledge, active faction projects, and incomplete memory jobs. Compare source coverage and prompt receipts before/after, including which lore and memory reached the narrator. Tune Jev thresholds from these examples; start report-only where a false positive could change canon.
- Run `npm run check`, focused tests, and build. Exercise a real server-bound story after starting the new artifact: inspect the provider screen, effective GameMaster/tool settings, turn and subagent receipts, canonical events/records, vault projection, and rendered Memory & Context and Player Guidance controls. A green source/build check alone does not establish the running result.
- Keep a rollback path for the new Memory & Context routing and Jev world decisions. Retired service settings are backed up by migration; disabling Jev returns faction moves to the existing deterministic planner and leaves NPC background actions idle.
